# ADR-0001. Конкурентные изменения остатков

**Статус:** принято для v0.1.0.

## Контекст

Два менеджера одновременно могут попытаться удержать последнюю единицу одного SKU. Расчёт доступного остатка:

available = physical − reserved − blocked.

- physical: сумма qty из неизменяемых stock_movements (по товару/складу/ячейке/партии);
- reserved: активные резервы за вычетом уже отгруженного;
- blocked: действующие блокировки stock_blocks.

Прямого изменения остатков через API нет.

## Решение

Каждая операция, затрагивающая SKU на складе, захватывает строку stock_guards(product_id,warehouse_id) через SELECT ... FOR UPDATE в SQL-транзакции. Для операций с несколькими парами блокировки захватываются в детерминированном лексикографическом порядке.

Только после блокировки читаются агрегаты. Если свободного товара недостаточно, вся транзакция отменяется и сервер возвращает HTTP 409 с доступным количеством.

Отгрузка одновременно создаёт расходное движение и закрывает резерв. Перемещение записывает расход и приход как атомарную пару. UPDATE/DELETE для stock_movements и audit_events блокируются триггером.

Idempotency-Key сохраняется вместе с ответом в idempotency_records и исходными изменениями, в одной транзакции. Коллизия ключа с другим содержимым запроса возвращает 409. X-Request-Id связывает действия с журналом.

## Компромиссы и риски

- SQL-агрегаты из журнала проще проверять, однако на миллионах движений потребуется профилирование и возможная транзакционная проекция.
- Операции одного SKU/склада сериализуются, отдавая приоритет целостности.
- Системный администратор PostgreSQL может заменить триггеры. Для production нужна отдельная ограниченная БД-роль для API.
- PWA хранит черновики локально, но они не имеют силы до подтверждения сервером.
- Transactional outbox уже сохраняет события, но worker пока моделирует внешний REST-вызов записью в лог. Реальная доставка требует отдельного адаптера и повторов.

**Отвергнуты:** прямое изменение счётчиков без журнала, Redis как источник истины, read-check-write без блокировки.
