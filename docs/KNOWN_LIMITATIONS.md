# Ограничения v0.3.0

- CI теперь собирает p50/p95/p99 для 60 отдельных одновременных пользователей на чтении каталога/остатков и отдельную проверку pg_dump/pg_restore. Полная смешанная нагрузка AT-10 (350 заказов/3000 движений) и production RTO менее 30 минут по-прежнему не подтверждены.
- Двухролевые браузерные E2E добавлены в CI (мобильный Chromium и desktop Firefox); отдельная ручная проверка настоящего смартфона и аудит безопасности всё ещё необходимы.
- Многострочные заказы и распределение по складам доступны в UI, но расширенные инструменты пакетного редактирования и оптимизация для очень длинных заказов ещё требуют доработки.
- Выбор позиции для возврата теперь встроен в UI; последовательность раздельных возвратов по разным ячейкам требует расширенной UX-проверки.
- Отсутствуют интерфейсы администрирования всех справочников (зоны, ячейки, партии, пользователи); действия доступны через API.
- Смена пароля и отзыв всех JWT сеансов реализованы через token_version, однако отсутствуют MFA и распределённый rate-limit. Перед публичной установкой необходим дополнительный security-hardening.
- Утверждение пересчёта блокируется при новых движениях после watermark журнала или появлении нового ненулевого остатка; автоматической перебазировки снимка пока нет, нужна повторная инвентаризация.
- Нет настоящей ERP/1С-интеграции. Outbox worker только моделирует доставку.
- PWA не отправляет движения offline: черновики остаются локальными до подключения.
- В demo Compose одна роль PostgreSQL создаёт схему и обслуживает API; в production права следует разделить.
- Описание отражает первую рабочую версию, а не завершение всех 22 функциональных требований.
