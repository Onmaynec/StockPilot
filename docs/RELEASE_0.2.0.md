# StockPilot v0.2.0 — Операционные сценарии и управление доступом

## Реализовано

### Заказы и комплектация
- Многострочный редактор заказа: поисковая выдача SKU с сервера (до 40 результатов), отдельный склад и количество в каждой строке, добавление и удаление строк.
- На экране отбора добавлен фильтр «Ожидают/Недобор», «Все», «Завершённые».
- Старший смены и администратор могут согласовать зафиксированный недобор из карточки задания. До решения недобора отгрузка остаётся заблокирована.
- Детали заказа показывают строки, задания и отгрузки; допускается отмена неотгруженного заказа с проверкой на сервере.

### Возвраты
- Новый GET /api/v1/shipments/{id}/returnable выдаёт только реально отгруженные и ещё не возвращённые количества с учётом склада и роли.
- Форма возврата больше не требует вручную копировать UUID резерва: выбор позиции и ячейки, проверка максимума, показ уже возвращённого количества.

### Безопасность и схема данных
- Миграция 002 добавляет users.token_version.
- JWT включает версию сеанса. POST /api/v1/auth/change-password отзывает все прежние JWT после проверки текущего пароля.
- POST /api/v1/auth/logout-all отзывает сеансы без смены пароля.
- Инкремент версии и запись аудита атомарны. Бывшие сессии отвергаются при каждом запросе.
- Однократный сервис migrate применяет новые изменения схемы на существующих томах без удаления PostgreSQL.

### Качество
- Интеграционные проверки возврата, повторяемости, разделения полномочий, нескольких строк и смены пароля.
- E2E Playwright для мобильного Chromium и Firefox: менеджер → кладовщик → отгрузка → проверка статуса; проверка отказа для запрещённого создания SKU.
- CI проверяет PostgreSQL, seed, backend-тесты, frontend build, Docker healthcheck и браузерные сценарии.

## Что ещё не заявляется закрытым

- AT-10: нагрузка 60 активных пользователей, p50/p95 и замеры ресурсов — требуется отдельный воспроизводимый протокол.
- AT-11: восстановление из резервной копии на отдельной БД с проверкой RTO — ещё не проведено.
- AT-12: браузерный E2E автоматизирован, но ручная приёмка со смартфона и проверка на реальном мобильном устройстве остаются открыты.
- Issue #4: разграничение прав PostgreSQL мигратор/API, распределённый rate-limit, полная security-проверка и MFA не закрыты.
- Нет реального транспорта интеграции ERP: используется transactional outbox с имитацией внешней доставки.

Даты и фактические цифры тестов фиксируются в CI, а не подменяются ожиданиями.
