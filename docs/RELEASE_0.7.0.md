# StockPilot v0.7.0 — Backup & Recovery

Версия расширяет эксплуатационные инструменты WMS и закрывает функциональный пробел между наличием SQL-архива и восстановлением рабочего приложения.

## Что изменилось

- Добавлен опциональный контейнер **backup** в `compose.yml`: локальные резервные копии PostgreSQL после запуска и далее раз в 24 часа (конфигурируется), повтор при ошибке через 300 секунд, без открытых сетевых портов.
- `scripts/backup_rotate.sh`: атомарная запись custom-format `pg_dump`, проверка списка объектов через `pg_restore --list`, локальный SHA-256 sidecar, контроль доступа к каталогу бэкапов, блокировка параллельных запусков, автоматическое удаление старых архивов с сохранением **двух последних**.
- `scripts/schedule_backups.sh`: расписание внутри backup-контейнера.
- `compose.recovery.yml` и `scripts/recovery_drill.sh`: воспроизводимый изолированный стенд восстановления с собственной PostgreSQL-БД. Выполняется `pg_restore --exit-on-error`, переинициализируются прикладные права, поднимаются API, worker и nginx, проверяются служебные маршруты и получаются отпечатки базы.
- `scripts/recovery_fingerprint.sql`: сверка количества бизнес-объектов, неизменяемого журнала движений, аудита и агрегатов физических остатков.
- `scripts/backup.sh` больше не перезаписывает существующий архив и создаёт файл контрольной суммы. Разрушительное `scripts/restore.sh` требует осознанного разрешения, SHA-256 и остановленных API/worker/web.
- Расширен GitHub Actions CI: `docker compose` проверяет recovery-конфигурацию и проверяет синтаксис скриптов; создаёт архив, намеренно повреждает копию для отрицательной SHA-256 проверки и восстанавливает полный изолированный стек. JSON-отчёты включаются в artifact.
- Исправлена полнота CI API: добавлено применение `006_live_balances.sql` перед интеграционными тестами.
- Версии API/фронтенда обновлены до v0.7.0, документация обновлена.

## Ограничения

**AT-11 не считается закрытым** на основании демо-теста. Скрипт измеряет реальный запуск API/worker/web после восстановления дампа в Docker-стенде CI; целевой production RTO<30 минут требует отдельного испытания на полном объёме боевых данных. Backup-копии находятся на хосте, не шифруются самим приложением и не отправляются во внешнее защищённое хранилище. Для production необходимы шифрование, вынос за пределы хоста, мониторинг успешности и проверка восстановления по регламенту.

AT-10 (смешанная производственная нагрузка) и AT-12 (ручная мобильная приёмка) также остаются открытыми.

## Обновление

Сначала создайте и проверьте отдельную резервную копию. Затем `git pull origin main` и `docker compose up -d --build`. Профиль `backup` **по умолчанию выключен** — его включают отдельно после настройки `BACKUP_INTERVAL_SECONDS`/`BACKUP_RETENTION_DAYS`. Том PostgreSQL удалять нельзя. Полная инструкция: `docs/OPERATIONS.md`.

На временном GitHub-hosted стенде PostgreSQL 16 с демокаталогом **12 000 SKU**:
- Два последовательно запущенных backup-контейнера создали **два разных архива**; для обоих подтверждён SHA-256. Контрольное повреждение копии привело к ожидаемому отказу checksum.
- Из настоящего `pg_dump -Fc` развёрнут отдельный recovery Compose project. Время непосредственного `pg_restore` — **1 секунда**, время **полного изолированного восстановления — 18 секунд**, включая создание временной БД, запуск миграций и API/worker/nginx; `apiReady=true`, `webReady=true`, `workerStarted=true`, `fingerprintsMatch=true`.
- После проверки автоматически удалены контейнеры и том восстановления, основное окружение не останавливалось.
- Сценарий 60 отдельных пользователей, 600 авторизованных GET — **0 ошибок**, каталог p95 **307,69 мс**, остатки p95 **266,83 мс**, **291,84 запроса/с**.
- Дополнительный write-smoke из v0.6.0: 20 заказов, 8 успешных резервов и 12 ожидаемых отказов, 20 парных перемещений (40 проводок), инварианты сохранены.

**Интерпретация:** 18 секунд — результат на одноразовой демобазе и подготовленных Docker-образах конкретного CI; **не** гарантия RTO на продакшен-сервере, не проверка внешнего шифрованного хранилища и не независимая сертификация AT-11. AT-11 оставлен открытым.
