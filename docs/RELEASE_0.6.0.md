# StockPilot v0.6.0 — Balance Performance & Write Validation

## Производительность реестра остатков

- Устранён эффект **N+1** в `GET /api/v1/stocks`: прежняя реализация вызывала `stock_total()` в цикле для каждого SKU-склада, генерируя до 51 SQL-запроса на страницу из 50 позиций.
- Новый SQL получает только доступную пользователю страницу в `MATERIALIZED` CTE; агрегации physical/reserved/blocked выполняются для строк этой страницы внутри того же SQL. Возвращаемые поля, права на склады, сортировка, пагинация и `available = physical - reserved - blocked` сохранены.
- Добавлена миграция `006_live_balances.sql` с частичными индексами `idx_reservations_live_stock` и `idx_blocks_live_stock`. Индексы помогают выборкам по действующим резервам и блокировкам. Миграция повторно применима; на большой production-БД первый запуск индекса планируйте на период низкой нагрузки.
- Регрессионные тесты проверяют активный резерв, блокировку и её снятие, пустую выдачу, складской RBAC и пагинацию для двух складов.

## Ограничения складского доступа

- Исправлена фильтрация списков `GET /receipts` и `GET /transfers`: документ не раскрывается сотруднику, если хотя бы одна его строка или конечная ячейка находится на чужом складе. Администратор продолжает видеть все документы. Добавлен отдельный негативный тест для обоих случаев.

## Смешанные складские операции

- Добавлен `backend/app/write_profile.py`: опциональный тест через настоящий API, работающий только при двойном явном разрешении и точной проверке demo seed.
- В сценарии создаются тестовые SKU, партия, приёмка на 8 единиц и 20 заказов. При 20 конкурентных попытках резерва ожидается ровно 8 успехов и 12 отклонений `INSUFFICIENT_STOCK`.
- Выполняются реальные перемещения товара между двумя ячейками. Их количество задаётся через `STOCKPILOT_WRITE_TRANSFERS`; стандартный CI использует 20 перемещений, что даёт 40 строк журнала.
- Проверяется, что все перемещения проведены, их сумма равна нулю, общий физический остаток исходного SKU не изменился, а новый SKU содержит ровно 8 физических и 8 зарезервированных единиц.
- JSON отчёты с p95 для операций сохраняются как артефакты CI вместе с read-load и восстановлением PostgreSQL.
