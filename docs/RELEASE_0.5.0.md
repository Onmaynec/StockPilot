# StockPilot v0.5.0 — Warehouse Administration

Версия расширяет ежедневное администрирование складской системы. Раньше создание зон, ячеек и сотрудников было доступно через API, но в интерфейсе для этого не хватало рабочего места.

## Новое в интерфейсе

- Раздел **«Администрирование»** в боковом меню виден только администратору. Данные остальных ролей не загружаются и не передаются в их интерфейс.
- Вкладка **«Сотрудники»**: список пользователей с ролями и статусами, создание сотрудника с назначением складов, блокировка и разблокировка, изменение складских назначений.
- Вкладка **«Склады и ячейки»**: выбор склада, просмотр зон и ячеек, создание склада, зоны и ячейки с проверкой на сервере.
- Вкладка **«Партии товаров»**: поиск SKU, просмотр существующих партий, регистрация партии и необязательного срока годности.
- Тёмная визуальная система и мобильная адаптация этого экрана согласованы с остальными разделами.

## Правила доступа и аудит

- `POST /api/v1/users/{id}/access`: атомарная замена полного списка разрешённых складов. Нельзя назначить несуществующий или неактивный склад. При фактическом изменении повышается `token_version`, все старые JWT пользователя недействительны; повтор одинаковых прав не отзывает сеансы повторно.
- `POST /api/v1/users/{id}/status`: блокировка и восстановление учётной записи. Заблокированный пользователь не проходит вход и не может использовать ранее выданный JWT. Самоблокировка администратора отвергается.
- `GET /api/v1/users` теперь возвращает также `warehouse_ids`, без паролей или секретов. Создание нового сотрудника проверяет идентификаторы складов как UUID.
- История изменения полномочий сохраняется в `audit_events` как `user.warehouses_change` и `user.status_change`.
- nginx перезаписывает `X-Real-IP` адресом подключившегося клиента, чтобы PostgreSQL rate-limit из v0.4.0 различал клиентов за общим nginx-прокси. Учитываются только явно доверенные proxy peer-адреса.

## Поиск и производительность

В двух прогонах первого кандидата v0.5.0 нагрузочный baseline 60 пользователей/600 чтений не достиг цели p95≤500 мс для каталога и остатков (645/583 мс и 606/564 мс соответственно; HTTP-ошибок не было). Для устранения дорогих последовательных сканирований по `ILIKE '%...%'` добавлены индексы `pg_trgm` на SKU, название и штрихкод. Измерение после миграции и обновления статистики PostgreSQL фиксируется отдельно в CI; AT-10 нельзя закрывать без проверки смешанной write-нагрузки.

## Тесты

Добавлены интеграционные тесты RBAC для новых административных операций, атомарности назначений и отзыва сеансов, а также браузерный E2E для создания склада, зоны, ячейки, сотрудника и партии и блокировки учётной записи.

### Результаты GitHub Actions

На коде v0.5.0 с миграцией `005_catalog_search.sql` прошли **25 интеграционных backend-тестов**, **6 браузерных E2E** (мобильный Chromium и desktop Firefox), сборка React, запуск Docker и проверка ограниченных прав PostgreSQL.

Для проверки производительности после `ANALYZE products` использовался один и тот же сценарий: 60 раздельных пользователей, 600 авторизованных GET (300 каталог + 300 остатки), 0 HTTP-ошибок.

## Ограничения

- MFA и индивидуальное управление устройствами/сессиями не внедрены; все открытые сеансы при изменении прав отзываются одновременно.
- Интеграция ERP/1С всё ещё работает через имитатор outbox.
- AT-10/AT-11/AT-12 не считаются закрытыми только из-за добавленных тестов. Для AT-12 нужна ручная мобильная приёмка.
- Создание пользователей доступно только администраторам; UI не выполняет прямое изменение остатков.
- В версии добавлена безопасная для повторного применения миграция `005_catalog_search.sql` с расширением `pg_trgm` и индексами поиска SKU, названия и штрихкода. На больших производственных базах создание GIN-индексов потребует планового окна обслуживания. Перед развертыванием проверьте, что `.env` содержит раздельные учётные данные владельца PostgreSQL и прикладного пользователя.

## Обновление

Создайте резервную копию, затем выполните `git pull origin main` и `docker compose up -d --build`. Тома БД не удаляйте. Проверьте `docker compose exec -T api python -m app.security_check`, вход под администратором и работу раздела «Администрирование».

GitHub Releases и Git-тег публикуются отдельно после проверки CI.
