# ADR-0002. Отзыв сеансов и обновление существующей схемы

**Статус:** принято в 0.2.0.

## Проблема

Сессионный JWT первоначально был самодостаточен и принимался до истечения восьми часов. Смена пароля не прекращала прежние сеансы. При этом PostgreSQL выполнял SQL из /docker-entrypoint-initdb.d только при создании пустого тома, поэтому новые изменения схемы не могли надёжно попадать в уже работающие стенды.

## Решение

К каждой записи users добавляется целочисленный token_version, начальное значение 0. JWT включает ver. На каждом запросе сервер сверяет ver с текущей версией пользователя в PostgreSQL. Смена пароля после проверки PBKDF2-хеша, либо отзыв всех сеансов, увеличивает token_version в транзакции с событием аудита. Все ранее выданные токены становятся недействительными немедленно после фиксации транзакции.

Миграция 002_sessions.sql повторно применима с IF NOT EXISTS. На пустом томе PostgreSQL читает 001 и 002; на существующем томе одноразовый контейнер migrate выполняет 002 до запуска API/worker. Миграции должны быть отдельными, проверяемыми и последовательными; удалять том ради обновления запрещено.

## Оставшиеся ограничения

- Нет индивидуального отзыва одного устройства: текущая операция отзывает все сеансы.
- JWT до завершения первоначальной миграции не может быть использован новым API. Пользователям требуется повторный вход.
- Для производственного развёртывания необходима отдельная БД-роль мигратора и ограниченные права приложений, без доступа к DDL и триггерам.
- Для нескольких реплик ограничитель запросов должен иметь общее хранилище. Локальный in-process rate-limit подходит только для одиночного контейнера.
