# StockPilot v0.8.0 — Mobile Picking & Assignment

Обновление посвящено работе кладовщика и старшего смены непосредственно в складской очереди. Сервер остаётся источником истины для назначения задач, резервов и согласования недоборов.

## Комплектация и мобильный интерфейс

- Старший смены или администратор назначает активное задание конкретному кладовщику прямо из карточки. В списке только действующие кладовщики, имеющие доступ к складу задания.
- Фильтр **«Мои активные задания»** ограничивает выборку задач на сервере по `assigned_to=current_user.id`; обычная очередь доступных складских задач сохранена.
- В карточке добавлены номер заказа, статус назначения и пользовательские подсказки по количеству. При недоборе отображаются недостающее количество и необходимость согласования.
- Перед записью недобора требуется подтверждение. Неверное, дробное и превышающее резерв количество блокируется в интерфейсе; сервер валидирует данные независимо от браузера.
- Ошибки получения доступа к камере и отсутствие `BarcodeDetector` отображаются прямо в карточке, доступен ручной ввод SKU/штрихкода без использования камеры.
- Увеличены размеры полей ввода и кнопок на небольших экранах. Никакие движения и резервы не проводятся без успешного подтверждения API.
- Черновики сканирования перенесены из постоянного `localStorage` в `sessionStorage` с ключом, содержащим ID сотрудника и задания. При выходе они удаляются; старые постоянные черновики очищаются при входе в приложение.
- Создание заказа ограничено 50 строками уже на кнопке добавления позиции. Многострочные и распределённые по складам заказы продолжают поддерживаться.

## Backend и права

- `GET /api/v1/picks?assignedToMe=true` — серверная фильтрация по назначенному сотруднику, с сохранением складской RBAC.
- `GET /api/v1/picks/assignees` — только для `admin`/`supervisor`, возвращает действующих кладовщиков и только разрешённые складские назначения; проверяет необщедоступный склад перед выдачей.
- Назначение, проверка исполнителя и переход `shortage_pending` → `accepted` остаются транзакционными операциями с аудитом.
- Дополнительные интеграционные тесты покрывают полномочия, складскую область, два задания, назначение и изменение состояния при недоборе.

## Браузерная проверка

Добавлен Playwright-сценарий `frontend/e2e/picking_v8.spec.cjs`: двухстрочный заказ, резерв, назначение старшим смены, личная очередь кладовщика, обычная сборка, недобор с подтверждением и согласование старшим смены. Сценарий исполняется на мобильном Chromium и desktop Firefox, вместе с ранее существующими E2E.

### Проверенные результаты v0.8.0

[GitHub Actions #43565943754](https://github.com/Onmaynec/StockPilot/actions/runs/43565943754) — **все четыре job успешны**: **30 backend-тестов**, **8 Playwright E2E** (mobile Chromium Pixel 5 и Firefox desktop), React build, Docker Compose.

Новый браузерный тест прошёл в обоих проектах: менеджер создал двухстрочный заказ и зарезервировал склад, старший смены назначил обе задачи кладовщику; кладовщик выбрал «Мои активные задания», подтвердил полную сборку первой задачи и недобор второй, старший смены согласовал этот недобор.

Параллельный read-only профиль CI: 60 пользователей, 600 GET, 0 ошибок; p95 каталога **297,30 мс**, p95 остатков **257,20 мс**, суммарно **286,55 запросов/с**. Изолированное восстановление PostgreSQL+API+worker+web заняло **18 секунд** на демонстрационном CI-стенде, контрольные отпечатки совпали. Эти значения не подтверждают production AT-10/AT-11.

Отчёты доступны в артефакте `stockpilot-07-disaster-recovery-evidence` CI (название существующего артефакта сохранено). Испытания на физическом телефоне и реальном аппаратном сканере остаются непроведёнными; **AT-12 по-прежнему открыт**. Общие AT-10, AT-11 и независимый аудит безопасности также не закрываются данной версией.

## Обновление

Сделайте резервную копию PostgreSQL, выполните `git pull origin main` и `docker compose up -d --build`. Новых SQL-миграций поверх v0.7.0 нет. Повторная авторизация на общем устройстве очищает предыдущие временные черновики.
