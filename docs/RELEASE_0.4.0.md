# StockPilot v0.4.0 — Security & Operations

## Что изменилось

### PostgreSQL: отдельный прикладной пользователь

- В миграционном контейнере с правами владельца создаётся независимая учётная запись `APP_DB_USER` (настройка нового пароля через `.env`). `DATABASE_URL` у API и worker ведёт только на неё.
- Прикладной пользователь может проводить складские операции, но не владеет таблицами, не создаёт схему и **не имеет UPDATE/DELETE в `stock_movements` и `audit_events`**. Физическая неизменяемость истории обеспечивается также триггерами PostgreSQL.
- `scripts/db_roles.sql` запускается после миграций, а `app.security_check` в CI отдельно проверяет отсутствие суперпользовательских полномочий, DDL и правки журналов.
- Новые установки автоматически применяют миграцию 004; существующие миграции 002/003/004 повторно запускаются безопасно.

### Distributed rate limit и доверенные прокси

- Убраны внутрипроцессные словари `_rate_buckets` и блокировка `_rate_lock`.
- Новая `rate_limit_counters` хранит только хешированные ключи и счётчики 60-секундных окон. Атомарный UPSERT обеспечивает общий предел для нескольких воркеров/реплик.
- Лимиты по IP: 30 входов в минуту, 2000 API-запросов в минуту; 429 содержит `Retry-After`. Worker удаляет устаревшие окна.
- Устранено доверие к подставляемому клиентом `X-Forwarded-For`; `X-Real-IP` рассматривается только при подключении от явно доверенного peer-адреса.
- API-ответы получают `Cache-Control: no-store`. При недоступности базы лимитер не разрешает запросы молча.

### Регрессии и эксплуатация

- Интеграционные тесты атомарности квот с параллельными потоками, 429, очистки исторических окон, ограничений доверенного прокси.
- В Docker CI проводится `python -m app.security_check` именно под прикладным пользователем.
- Полное обновление `.env` и ограничений среды описано в `README.md` и `docs/OPERATIONS.md`.

## Ограничения

**Не называем это завершённым независимым аудитом безопасности.** Нет MFA, индивидуального управления устройствами/токенами, внешнего IAM, ingress WAF, отдельного production-секретного хранилища. Распределённые квоты — фиксированные окна на PostgreSQL: нагрузочные характеристики отличаются от предыдущей версии и требуют проверки. Исходные AT-10/AT-11/AT-12 остаются открыты до полного подтверждения требований. Реальный ERP-провайдер по-прежнему не подключён.

## Обновление с v0.3.0

До обновления необходимо настроить **новую** учётную запись `APP_DB_USER`, отдельный пароль `APP_DB_PASSWORD` и `DATABASE_URL` с адресом прикладной роли. Не удаляйте том базы и не изменяйте `POSTGRES_USER` существующего кластера. Подробная инструкция: `docs/OPERATIONS.md`.

После успешного обновления проверьте `docker compose exec -T api python -m app.security_check`, наличие сессий, резервов и историю движений.
