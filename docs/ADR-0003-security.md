# ADR-0003. Database principal separation and shared rate limits

**Статус:** принято для v0.4.0.

## Риск

В v0.3.0 \`DATABASE_URL\` использовал владельца схемы PostgreSQL. Компрометация API могла дать злоумышленнику возможность отключить триггеры и переписать историю через DDL. Лимиты запросов были внутрипроцессными и доверяли части неаутентифицированного заголовка \`X-Forwarded-For\`.

## Решение

1. Отдельная учётная запись \`APP_DB_USER\` создаётся только через мигратор с правами владельца. App/worker не получают пароля владельца. Разрешены DML операции, нужные API, кроме UPDATE/DELETE для таблиц журналов. API не владеет schema/table/triggers и не имеет CREATE on public schema.
2. Секрет прикладной роли задаётся вне исходников. При миграции проверяется, что owner и app не совпадают.
3. Rate-limit реализован через атомарный PostgreSQL \`INSERT ... ON CONFLICT DO UPDATE RETURNING hits\` на ключе (хеш источника/назначение, окно epoch/60). Счётчик не содержит исходных IP и не теряется при перезапуске процесса.
4. Переключение сетевого адреса допускается только через \`X-Real-IP\`, когда адрес TCP-peer входит в \`TRUSTED_PROXY_CIDRS\`. \`X-Forwarded-For\` игнорируется. Для остальных используется реальный адрес соединения.

## Следствия и ограничения

- PostgreSQL является общим зависимым сервисом rate-limit; при его недоступности API fail-closed. Выделенный Redis не требуется (бюджет проекта 0), но операции счётчиков увеличивают нагрузку на БД.
- Фиксированные 60-секундные окна могут допускать пограничный burst; production ingress нуждается в дополнительном защитном пределе.
- Приложение всё ещё может добавлять новые строки журнала через INSERT, что необходимо для бизнес-операций. Это **не** криптографически защищённый append-only ledger.
- Выдача широких INSERT/UPDATE/DELETE на другие таблицы означает, что компрометация приложения остаётся критическим инцидентом. Полноценная SQL-level row security не внедрена; права складов контролируются API.
- Тесты с TRUNCATE запускаются **только** от изолированного owner CI, а запущенное приложение проверяется под ограниченной ролью.
